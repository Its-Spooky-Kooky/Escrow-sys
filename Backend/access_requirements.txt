================================================================================
A) DATABASE URI (MONGODB)
================================================================================
You need a MongoDB database for your off-chain user profiles and gig details.

OPTION 1: MongoDB Atlas (Cloud Database - Free & Recommended for Sharing)
  1. Go to: https://www.mongodb.com/cloud/atlas/register and create a free account.
  2. Create a Project: Name it "Escrow-Sys" or similar.
  3. Deploy a Database: Select the "M0" (Free Tier) cluster option.
     * Select your preferred region (e.g., AWS/Google Cloud server closest to you).
     * Click "Create Deployment".
  4. Security Setup:
     * Authentication: Create a Database User by choosing "Username and Password". 
       Save the password securely! (e.g. Username: "escrow_admin").
     * Network Security: Click "IP Access List". Add your current IP address, or add 
       `0.0.0.0/0` (allows connections from anywhere, which is useful during development).
  5. Get Connection String:
     * Once your cluster is ready, click "Connect".
     * Choose "Drivers" (Node.js).
     * Copy the connection string. It will look like:
       `mongodb+srv://escrow_admin:<db_password>@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority&appName=Cluster0`
     * Replace `<db_password>` with the actual password you created in step 4.
     * Put this in your `.env` as:
       `MONGO_URI=mongodb+srv://escrow_admin:YOUR_PASSWORD@cluster0.abcde.mongodb.net/escrow?retryWrites=true&w=majority`

OPTION 2: MongoDB Community Server (Local Database - Offline & Fast)
  1. Go to: https://www.mongodb.com/try/download/community
  2. Download and run the MSI installer for your OS (Windows).
  3. During installation, check "Install MongoDB as a Service" and select "Install MongoDB Compass"
     (a beautiful graphic tool to see your database tables).
  4. Once installed, MongoDB will run in the background on your machine.
  5. Put this connection string in your `.env`:
     `MONGO_URI=mongodb://localhost:27017/escrow`

================================================================================
C) JWT SECRET KEY GENERATION
================================================================================
The JWT secret is a private key used to cryptographically sign backend login sessions.
Never use a simple dictionary word. Here is how to generate a secure, premium key:

How to generate using your command line:
  1. Open your terminal in the backend folder.
  2. Run this node interactive command:
     `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`
  3. Copy the long random hexadecimal string output.
  4. Paste this in your `.env`:
     `JWT_SECRET=paste_your_generated_hex_string_here`

================================================================================
D) SMART CONTRACT ADDRESSES (STEP-BY-STEP PROCESS)
================================================================================
The backend must know the smart contract's interface (ABI) and where it lives (Address)
on-chain to listen to events and verify actions. Here is the step-by-step process:

Step 1: Obtain compilation artifacts from your friend (Contract Developer)
  When your friend compiles their Solidity code (using `npx hardhat compile` or `forge build`), 
  the tool generates compiler artifact JSON files.
  - You need two files: `EscrowFactory.json` and `Escrow.json`.
  - These contain the "ABI" (Application Binary Interface), which is a translation map 
    allowing Node.js to communicate with compiled blockchain bytecode.

Step 2: Save the ABIs in the Backend folder
  1. Inside `Backend/src/config/`, create a folder named `abis` if it doesn't exist yet.
  2. Create two files:
     - `Backend/src/config/abis/EscrowFactory.json`
     - `Backend/src/config/abis/Escrow.json`
  3. Copy and paste the entire JSON array or artifact content received in Step 1 into these files.

Step 3: Obtain the deployed contract address
  1. Once your friend deploys the contract to their target network (Local Hardhat, Sepolia, 
     or Polygon), their deployment terminal will print the address.
     * Example output: `EscrowFactory deployed to: 0x959922bE3CAee4b8Cd9a407cc3ac1C251C2007B1`
  2. Ask your friend for this address string.

Step 4: Update the .env configurations
  1. In the `Backend/.env` file, add the address string:
     `ESCROW_FACTORY_ADDRESS=0x959922bE3CAee4b8Cd9a407cc3ac1C251C2007B1`
  2. The backend code will load this address using `process.env.ESCROW_FACTORY_ADDRESS` and combine 
     it with the loaded `EscrowFactory.json` ABI to start listening for transactions in real-time.

4. SIMULATION AND TESTING ASSETS (FOR DECENTRALIZED AUTH)
--------------------------------------------------------------------------------
To test our passwordless cryptographic wallet login flow without needing a real frontend 
or clicking through MetaMask, we can simulate the entire Web3 signature process in Node.js.

================================================================================
STEP-BY-STEP FLOW FOR CRYPTOGRAPHIC SIGNATURE TESTING
================================================================================

Step 1: Generate a temporary test wallet
  We can write a quick simulation script (`simulate_login.js`) that creates a temporary 
  virtual wallet. In Ethers.js, this is done with:
  `const wallet = ethers.Wallet.createRandom();`
  This virtual wallet behaves exactly like a real hardware or browser wallet (e.g., MetaMask).

Step 2: Obtain the unique Nonce challenge
  Our script makes an HTTP POST request to the local backend `/api/auth/nonce` 
  sending the wallet address:
  ```json
  { "walletAddress": "0xYourVirtualWalletAddress" }
  ```
  The backend will:
  - Generate a secure random string (e.g., `nonce_9f3b8a1c...`).
  - Save it in the MongoDB user database.
  - Return this nonce to the testing script.

Step 3: Cryptographically sign the Nonce
  Our simulation script signs the nonce using the virtual wallet's private key:
  `const signature = await wallet.signMessage(nonceFromServer);`
  This returns a cryptographic hash string (a signature), which proves ownership of the 
  private key without ever transmitting or exposing the private key itself.

Step 4: Submit signature for verification
  The script makes an HTTP POST request to the backend `/api/auth/verify` sending:
  ```json
  {
    "walletAddress": "0xYourVirtualWalletAddress",
    "signature": "0xCryptographicSignatureStringReturnedInStep3"
  }
  ```
  The backend will:
  - Recover the signer's address from the signature using `ethers.verifyMessage(nonce, signature)`.
  - Compare the recovered address to the submitted `walletAddress`.
  - If they match perfectly, it issues a signed JWT token representing the authenticated session!

================================================================================
HOW TO RUN AN AUTOMATED SIMULATION SCRIPT
================================================================================
We can create a lightweight script inside `Backend/src/utils/simulateAuth.js` to run this:

```javascript
const { ethers } = require("ethers");
const axios = require("axios");

async function testWeb3Auth() {
  const BACKEND_URL = "http://localhost:5000/api";
  
  // 1. Create temporary wallet
  const wallet = ethers.Wallet.createRandom();
  console.log(`Generated Test Wallet: ${wallet.address}`);

  // 2. Fetch Nonce from Backend
  const nonceRes = await axios.post(`${BACKEND_URL}/auth/nonce`, {
    walletAddress: wallet.address
  });
  const nonce = nonceRes.data.nonce;
  console.log(`Fetched Nonce from Backend: ${nonce}`);

  // 3. Cryptographically Sign Nonce
  const signature = await wallet.signMessage(nonce);
  console.log(`Generated Cryptographic Signature: ${signature}`);

  // 4. Verify Signature & Log In
  const verifyRes = await axios.post(`${BACKEND_URL}/auth/verify`, {
    walletAddress: wallet.address,
    signature: signature
  });
  
  console.log("Authentication Response Received:", verifyRes.data);
  console.log("SUCCESS! JWT Session Token Issued:", verifyRes.data.token);
}
```

This simulation process guarantees 100% correct decentralized login validation offline, 
independent of any frontend development progress.
